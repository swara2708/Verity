# Verity — Backend API & AI Intelligence Subsystem

Bias-Aware 360° Performance Review Intelligence System built with **Python**, **FastAPI**, **Supabase (PostgreSQL + RLS)**, and **Google Gemini 2.0 Flash AI**.

---

## 🌟 Tech Stack

- **Framework**: FastAPI (Python 3.10+)
- **Database**: Hosted Supabase PostgreSQL (SQLModel ORM) with Row Level Security (RLS)
- **AI / LLM Engine**: Google Gemini API (`gemini-2.0-flash` via `google-generativeai`)
- **Authentication**: JWT (JSON Web Tokens) with server-side role gating (`hr_admin` vs `employee`/`manager`)

---

## 🚀 Quick Start

### 1. Install Dependencies
```bash
cd backend
pip install -r requirements.txt
```

### 2. Configure Environment Variables
Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```

Set your configuration in `.env`:
```env
# JWT Secret Key
JWT_SECRET=verity-secret-key-360-review-intelligence-2026

# Google Gemini API Key
GEMINI_API_KEY=your_gemini_api_key_here

# Supabase PostgreSQL Connection String & API Keys
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your-supabase-service-role-key
VERITY_DB_FILE=postgresql://postgres.yourproject:password@aws-0-pooler.supabase.com:6543/postgres
```

### 3. Run the Backend Server
```bash
uvicorn backend.main:app --port 8000 --reload
```
- **API Health Endpoint**: [http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health)
- **Interactive Swagger Docs**: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

## 🗄️ Database Architecture & RLS Security

All tables are multi-tenant and scoped to an `org_id`. Cross-tenant isolation is enforced at the database layer using PostgreSQL Row Level Security (RLS) policies defined in `backend/db/rls_policies.sql`.

### Core Schema:
- **`organizations`**: Company profiles, review cycle dates, and bias thresholds.
- **`users`**: Employee and HR accounts with status gating (`pending` | `active` | `rejected`).
- **`invites`**: Secure signup invite tokens generated by HR admins.
- **`feedback_entries`**: 360° feedback items (self, peer, manager).
- **`daily_drafts`**: Ongoing employee work logs and daily progress notes.
- **`evidence`**: Verified outcomes, metrics, and PR links.
- **`reviews`**: Synthesized performance review reports and approval states (`draft` | `needs_input` | `approved`).
- **`bias_reports`**: Deterministic recency scores, diversity metrics, and audit flags.

## 🤖 Multi-Agent Review Pipeline (`backend/reviews/agents/`)

1. **Evidence Retrieval Agent (`evidence_agent.py`)**:
   - Collects all feedback entries, daily drafts, and formal evidence items.
   - Matches review claims directly against evidence items and daily logs using Gemini 2.0 Flash.

2. **Synthesis Agent (`synthesis_agent.py`)**:
   - Synthesizes 360° logs into a structured review report containing an **Executive HR Summary** (`hr_summary`), strengths, growth areas, impact highlights, and goal progress.

3. **Bias Detection Agent (`bias_agent.py`)**:
   - Pure Python engine computing **Recency Score** (% of feedback from last 2 weeks), **Source Diversity Score**, and **Unsupported Claims Count**.

4. **LLM Client Wrapper (`llm_client.py`)**:
   - Encapsulates Google Gemini API calls (`gemini-2.0-flash`) via `call_llm(prompt)` with markdown code fence stripping and JSON parsing.

## 📡 API Reference Summary

### Auth (`/api/auth`)
- `POST /api/auth/signup-hr`: First HR user creates organization.
- `POST /api/auth/login/hr`: HR portal login.
- `POST /api/auth/login`: Employee / manager login.
- `GET /api/auth/me`: Fetch authenticated user profile.

### Invites (`/api/invites`)
- `POST /api/invites`: HR creates invite link.
- `GET /api/invites/{token}`: Public invite details for registration page.
- `POST /api/invites/{token}/register`: Invitee submits registration (creates `pending` status user).

### HR Queue & Overview (`/api/hr`)
- `GET /api/hr/requests`: List pending user registration requests.
- `POST /api/hr/requests/{user_id}/approve`: Approve user (flips status to `active`).
- `POST /api/hr/requests/{user_id}/reject`: Reject user request.
- `GET /api/hr/overview`: Organization-wide employee review status dashboard.

### Evidence & Drafts (`/api/evidence`, `/api/daily-drafts`, `/api/feedback`)
- `POST /api/evidence` / `GET /api/evidence/{employee_id}`
- `POST /api/daily-drafts` / `GET /api/daily-drafts/{employee_id}`
- `POST /api/feedback` / `GET /api/feedback/{employee_id}`

### Reviews (`/api/reviews`)
- `POST /api/reviews/generate`: Trigger evidence retrieval, synthesis, claim matching, and bias analysis.
- `GET /api/reviews/{id}`: Fetch review report, HR summary, claim evidence, and bias report.
- `POST /api/reviews/{id}/approve`: HR approves review report.
- `POST /api/reviews/{id}/reject`: HR sends back review report (`status: needs_input`).
